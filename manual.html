EranTerm

User Manual. A local-first desktop manager for your servers: terminals, files, logs, metrics, deployments, and an AI assistant that only runs what you approve.

Getting started

  1. Click ＋ New connection on the Home page.
  2. Choose the type (SSH or RDP), then enter the host, port, and login: a username with a password or private key, or a saved User.
  3. Optionally set a group, tags, details, and mark it as a favorite. Then click Save.
  4. Click ▶ SSH on the server. Each connection opens in its own tab at the top of the window, on the module chosen in Settings (File Manager by default). ⌂ Home always takes you back. Drag tabs to reorder them. If a connection fails or drops, ⟳ Reconnect failed appears at the right of the tab row and reconnects all of them in place. A server's group is shown above its name at the top of its page.

The + at the right of the tab row opens a localhost tab: a terminal on this computer (your login shell), with terminal sessions, scripts and AI like any server. It has no File Manager, Logs or Metrics. Available on macOS and Linux.

The first time you connect, EranTerm remembers the server's host key. If that key changes later, EranTerm accepts the new one and warns you, so you can check it was expected (for example after a reinstall).

Home: servers & groups

  • Search filters by name, IP, user, or tag.
  • All Servers, Favorites, and each group in the side menu filter the table. Click a column header to sort.
  • Groups: click ＋ next to Groups to create one, or type a new group name when you edit a server. You can rename or delete a group from its row; deleting a group keeps its servers.
  • Group colors: in the group's Edit dialog, pick a soft color (or none). It tints the group's row on Home, its entry in the side menu, and the tabs of that group's servers.
  • The State column shows whether the server answers: green = available, red = not available, grey = not checked yet. Hover the dot for the date and time of the last check.
  • The ▶ SSH and 🖥 Desktop buttons (RDP, VNC or Screen Sharing) each show a dot for their own protocol: green when its port answers, red when it doesn't. Hover for the time of the check.
  • Checks run in the background and never slow down the app or your connections: one quick TCP connection per port, 2 s timeout, every minute by default. Change the interval or turn checking off in Settings → Server Availability; turn it off for one server with Check availability in its Edit dialog.
  • When a server goes down or comes back up, you get a desktop notification (see Settings → Notifications).
  • The Alerts column shows servers that are over a CPU, memory, or disk limit you set (see Metrics).
  • ‹ folds the side menu down to icons.

Users (saved logins)

Save a username with a password and/or private key once, then pick it under Login for any number of servers. When you change the saved user, every server that uses it gets the change.

Windows & RDP

  • Desktop opens Remote Desktop: Windows App on macOS (from the Mac App Store), or mstsc on Windows. A saved password is copied to the clipboard for the login prompt and cleared after 45 seconds.
  • ▶ SSH uses Windows OpenSSH with the same login (DOMAIN\user when you set a domain), so you also get the terminal, files, logs (from PowerShell), and metrics.

File Manager

  • Browse folders, type a path and press Enter, or use Home folder and Parent folder.
  • Upload: drag files or folders from your desktop into the window. Download: use the row action. Folders are transferred as .tar.gz.
  • Transfers show their progress at the bottom of the window. Columns sort when you click their header.
  • Open any folder in a side terminal or in the main terminal, copy a file's path, or Add to Logs to tail a file.

Terminal & scripts

  • A full shell. You can open several sessions per server.
  • As you type, command suggestions come from this server's history and from common commands.
  • Scripts: a searchable library of commands and multi-line scripts, with tags. Click one to run it in the terminal. You can import and export scripts (.json, .sh, .txt), and re-add any built-in scripts you deleted.

Logs

  • Add as many log sources per server as you need, for example /var/log/syslog.
  • Live turns tailing on and off. Choose how many lines to load (200–5000).
  • INFO, WARN, and ERROR lines are colored. Filter by level or by time ("newer than").
  • Search can highlight matches or show only matching lines. Clear empties the screen without changing the file, and Download saves the full log file.

Metrics & alerts

  • Shows CPU, memory, and disk usage, plus top processes sorted by CPU or memory.
  • Set an alert limit on any gauge, and EranTerm notifies you when the server goes over it.
  • Maintenance actions: Clear cache / buffers, Clean disk (temp files and old logs), and ending a process. These need root, so the user needs passwordless sudo or a saved password.

Deployments

A deployment runs the same steps on many servers, one at a time or in parallel. You build it as a flow:

  1. Target servers come first (see below).
  2. Then add steps in the order they should run, with ＋ Command / script, ＋ Verification and ＋ Files. ⧉ Repeat last step adds a copy of the last one. Each step can be moved up or down, duplicated or removed.
  • Command / script: a command or a multi-line script (#!/bin/bash supported), typed or taken from the script library. A non-zero exit code fails that server.
  • Verification: a log check (a pattern is present or absent), a TCP port check, or a script exit code check, with an optional wait time. Choose whether a failure stops the deployment or only raises an alert.
  • Files: files and folders copied to every target server. Folders keep their structure.

The strip at the top of the builder draws the whole flow: servers → each step → Done. Empty steps are shown dashed and are skipped when the deployment runs. Click a step in the strip to jump to it.

While it runs, each server shows every step of the flow with its status. You can follow it live and reopen the last run's results afterwards. Deployments saved by older versions (Pre-deploy / Files / Deploy / Post-deploy) open as steps in that same order.

  • Target servers: narrow the list by group or by typing (name, host, tag or details), then use Select shown / Clear shown. Filtering never changes servers you've already selected.
  • ■ Stop ends the run right away: commands still running on the servers are stopped (with their child processes), and servers not started yet are skipped.
  • You get a desktop notification when a deployment finishes.

AI assistant

  • In the Terminal, describe what you want, and the AI suggests a command. Nothing runs until you approve it.
  • Ask AI in Terminal or Logs analyzes what's on screen, or the log lines that are currently shown.
  • Set it up in Settings → AI: choose a provider (Anthropic, OpenAI, Gemini or Cursor), paste an API key, and pick a model (Load models asks the provider for its current list). Test checks the key without saving it.
  • Cursor runs the Cursor CLI on this computer (cursor-agent; install with curl https://cursor.com/install -fsS | bash). The API key is optional: without one it uses your cursor-agent login. Model auto lets Cursor choose.
  • Text is sent to the provider only when you click Ask AI or request a command.

Settings & updates

Settings is split into tabs.

General

  • Theme: System, Light, or Dark.
  • Server connection default module: the module a server opens on when you connect: File Manager (default), Terminal, Logs or Metrics.
  • Reopen the open server tabs when the app starts: the tabs open when you quit (in their order, including localhost) reconnect at the next start. Off by default.

Server Availability

  • Turn background checks on or off for all servers, and set how often they run (seconds, default 60), on one line.

Updates

  • Update automatically: EranTerm checks for a new release at startup and every 6 hours.
    • Windows: the update downloads in the background. Restart when you're asked, or it installs the next time you quit.
    • macOS: you're offered the download page. Open the new .dmg and drag EranTerm into Applications.

Logging

  • Optionally save the app log to eranterm.log in a folder you choose (default: ~/Library/Logs/EranTerm on macOS).
  • Debug Console: a live view of the app log. Open it with the ›_ Console button in the side menu, from Settings, or with Ctrl/⌘ + Shift + L.

AI

  • Provider, API key and model: see AI assistant.

Notifications

  • Desktop (OS) notifications for: a server going down or coming back up, a deployment finishing, and metric alerts. On by default.
  • Help → Version shows your version. Help → Check for Updates… checks right away. Help → User Manual (F1) opens this page.

Security & data

  • Passwords and API keys are encrypted with your OS keychain and never leave your machine, except when they're used to log in or to call the AI provider.
  • Everything is stored locally: servers, users, groups, scripts, and settings. Nothing is synced to a cloud.
  • Host keys are pinned after the first connection.
